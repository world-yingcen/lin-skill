# Lin-EVO｜Header、Footer 與內頁

先依 [EVO 範本查核](evo-preflight.md) 選擇匯入流程。整站 HTML 的共用結構、選單、系統功能及資源依目前工程師套件；下方指定舊元件與執行時載入規則僅適用舊流程。通用的視覺、導覽操作、Cookie／政策內容需求仍依案件套用；不把舊功能限制套進新版。

舊流程的靜態 HTML 使用以下載入規範；既有框架使用單一共用 Layout／元件，不額外加 fetch 載入器。RWD 依案件範圍。新站採下列導覽慣例；局部修改保留未在本輪調整範圍的既有行為。

## T13｜Header、Footer 與內頁

每個網站首次製作時，就要一起完成 Cookie 提示與隱私權政策頁面，不延後到另一次內頁階段。Cookie 樣式與文字統一依照 [evo263525 Cookie 指定參考](evo-cookie-reference.md)；製作前必讀，文案逐字保留，「隱私權政策」文字必須連到本案實際可開啟、有內容的政策頁面，不使用空連結或占位頁。

EVO 選單、root、漢堡、按鈕與語系以使用者指定的 [evo266200 Header 參考](evo-header-reference.md) 為工程依據；製作相關元件前必讀其結構、變數、狀態與來源限制，再依本案首頁調整樣式。

內頁麵包屑以 [evo263525 breadcrumb001 參考](evo-breadcrumb-reference.md) 為工程依據，保留其語意結構、class、data 屬性與目前頁標示，集中管理內頁共用樣式。

舊平台流程的案件都要完成搜尋結果頁，與共用 Header／Footer、Cookie 提示及隱私權政策頁一起納入首次網站製作的頁面清單。結構統一依 [evo266200 搜尋頁指定參考](evo-search-reference.md)，製作前必讀；搜尋入口必須連到本案搜尋頁，不能只有按鈕或空連結。搜尋頁公版 HTML／JS 不修改，CSS 以指定系統共用頁為基準，可依案件確認需求調整，未指定調整時忠實沿用參考；本案共用 Header／Footer 與系統 CSS 已有變數仍沿用。正式搜尋資料由本案平台提供。此系統頁例外優先於下方一般內頁風格規則。

FAQ 以 [禾雅 tpl-faq001 參考](evo-faq-reference.md) 為工程依據，沿用原生 details／summary 收合、Q 標記與資料契約，樣式配合本案首頁。

**舊流程的執行時載入方式**：首內頁在對應位置使用以下共用載入容器，每頁各一個；整站 HTML 不採此方式，建置時將共用來源輸出到每頁 HTML，必要直接子層與標記依工程師套件，不用空殼或 fetch 補齊：

```html
<div id="site-header" aria-busy="true"></div>
<!-- 本頁主要內容 -->
<div id="site-footer" aria-busy="true"></div>
```

- Header 與 Footer 各維護一份共用 HTML，由共用 JavaScript 載入；不要在各頁複製整份內容。共用 Navi HTML 使用 `<header>`，Footer 使用 `<footer>`，不重複放上述容器 ID；`<header>` 僅允許此全站 Navi 使用，其他區塊改用 `<div>` 等容器。
- 優先沿用前端工程師提供的切版基底之共用檔案位置、載入方式及初始化流程；基底未附時由 實作端 補齊並記錄路徑，不宣稱 clone 後已具備載入功能。
- 各容器內容載入成功後設定 `aria-busy="false"`，再初始化導覽、手機選單及相關互動，避免重複綁定。載入失敗需結束忙碌狀態並回報可辨識錯誤，不將空容器當成完成。
- 透過本機預覽伺服器驗證；確認首頁及不同目錄深度的內頁都能載入共用內容，Logo、圖片及導覽連結路徑正確。共用樣式沿用既有 Header／Footer SCSS 與 Common 架構。
- 實作端 品檢確認：修改共用內容會同步反映於首內頁、載入完成後容器不再忙碌、本輪範圍內的桌機／平板／手機選單正常，且沒有載入失敗或重複初始化錯誤。

- Header／Footer 依已確認設計實際製作並填入本案 Logo、選單、語系（如有）、連結、聯絡資料與頁尾內容，載入後提供完整可操作內容。
- 頁尾版權列只能保留以下完整 HTML（2026-10-05 使用者指定），**寫死、不因案件或已確認設計跟著改**；包含外層 `.copyright-bar`，結構、文字與連結逐字沿用，樣式可依案件 Footer 配色調整。不得另外加入 `copyright-owner`、`©`、年份、客戶公司版權文字、Copyright 或 All Rights Reserved，也不以 JavaScript 自動補上。既有頁尾若有這類額外版權內容，在處理該頁尾時移除，保留其他聯絡及公司資訊：

  ```html
  <div class="copyright-bar">
    <div class="copyright-text">Designed by<a href="https://www.webtech.com.tw/" target="_blank" class="copyright-link">米洛科技有限公司</a></div>
  </div>
  ```
- 首內頁共用一致風格與操作；需要更改已確認設計時列原因及影響，交使用者確認。不啟動角色交接或自行搜尋新母版。
- EVO 已有適用範本的功能（例如選單、分類、列表），優先沿用現有範本結構，再依目前首頁設計調整字型、色彩、尺寸與間距，不重新發明結構。先找本案既有元件、開發提供的範本，或使用者提供的既有網站案例；核對 HTML 層級、必要 class／ID／data 屬性、初始化與操作狀態，保留轉 EVO 所需的對應。記錄範本名稱／編號、來源、工程版本及可調整範圍，不搬用其他客戶素材。
- 既有案例與本案 EVO 版本不相容時，依本案開發規格修正必要差異並記錄原因，不直接照搬不適用的舊綁定，也不以版本不同為由整份重寫。缺少範本原始碼或新版整合資料時，先查可用來源並標出缺口；不能只憑截圖自造結構後宣稱可直接轉 EVO。此規則限於 EVO 已有範本的功能，不限制本案自訂創意區塊的構圖。
- 單純文章編輯器內容區可使用簡單 HTML／CSS 編排，不強制套系統列表版型；仍沿用首頁字型、色彩、間距、按鈕及品牌。關於我們、ESG、服務等核心頁依本案已確認設計維持首頁完成度；列表、下載、文章與表單以閱讀及操作穩定為主。不能因稱為內頁就簡化已確認的構圖或動態。
- 只有版型名稱或截圖，不能推定新版系統的資料綁定、初始化方式或後台整合規格。缺資料只標受影響功能整合後待驗，不把預覽完成當成後台整合通過。

## 全站導覽行為

首頁與內頁的 Nav／Footer 外觀、內容及操作一致；整站 HTML 不在原始共用 HTML 寫死目前頁面狀態，由系統依契約產生。Nav 下滑後固定在視窗頂端，不下滑隱藏；切換不跳版，錨點與焦點避開導覽高度，確認與釘選場景的層級。每頁視窗右下角都有一致的 Scroll Top，不只放 Footer，避免遮住 CTA、表單或浮動工具；可鍵盤操作、有清楚名稱，配合既有捲動引擎與減少動態設定。實測頁首、下滑、頁尾與回頂部。

## 系統電子表單

電子表單／聯絡我們表單依 [evo266200 電子表單指定參考](evo-eforms-reference.md) 核對公版 DOM、欄位標記及資源，與詢問車分開處理；外觀依本案調整，保留平台欄位與原生驗證／送出流程。舊電子表單樣式 B 不再列為現行公版選項。

## 系統公版詢問車

詢問車頁／抽屜沿用 EVO 公版功能，CSS 可依案件調整，公版 HTML／JS 不可修改；限制不擴及產品頁，切版端可新增 `.inquiry-group` 分組並調整加入按鈕位置，保留原生功能綁定。有使用需求時，完整沿用 [evo265987 指定架構](evo-inquiry-cart-reference.md) 的產品加入詢問、Header 側欄清單、確認頁與表單；不能自行改流程、重建 DOM／資料契約、取代系統 JS 或做另一套購物車。案件外觀以 CSS 調整，不改 vendor 原始檔；CSS 做不到的部分列工程師待處理。使用者要求的靜態 Demo 可另放模擬程式，正式接入前停用，不能與原生功能同時綁定。

產品分類選單依 [left_menu001 指定參考](evo-left-menu-reference.md) 沿用公版結構與操作：桌機用 CSS 保留案件設計，手機版下拉邏輯是公版，不改寫或另綁事件，下拉外觀依指定公版與案件要求調整；斷點與細節以本案確認值為準。

## 平台整合邊界

Cookie、回頂部及浮動 UI 的位置也須符合本案匯入結構，不能任意放在會被丟棄的 body 子層。工程師重畫規範若要求移除舊代理商署名，先區分舊站署名與本案已確認的公司版權需求；有衝突時具體列出，不默默刪除已確認文案。

不編造 CMS wrapper、模組 ID、資料綁定或 API；以本案開發規格為準。明列已支援、前端示範、待串接及未驗證。正式表單不擅自送出，前端示範不可顯示假的寄送成功。
