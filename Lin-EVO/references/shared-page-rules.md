# Lin-EVO｜Header、Footer 與內頁

先依 [EVO 範本查核](evo-preflight.md) 選擇匯入流程。整站 HTML 的共用結構、選單、系統功能及資源依目前工程師套件；下方指定舊元件與執行時載入規則僅適用舊流程；使用者明確指定的 FAQ 與分類側選單結構為例外，不受此概括限制。分類側選單優先沿用 evo266125 的 left_menu001，再依案件調整 CSS；若與當次匯入契約衝突，列明具體差異交工程師確認，不默默跳過範本或改造結構。通用的視覺、導覽操作、Cookie／政策內容需求仍依案件套用；不把舊功能限制套進新版。

舊流程的靜態 HTML 使用以下載入規範；既有框架使用單一共用 Layout／元件，不額外加 fetch 載入器。RWD 依案件範圍。新站採下列導覽慣例；局部修改保留未在本輪調整範圍的既有行為。

## T13｜Header、Footer 與內頁

每個網站首次製作時，就要一起完成 Cookie 提示與隱私權政策頁面，不延後到另一次內頁階段。Cookie 樣式與文字統一依照 [evo263525 Cookie 指定參考](evo-cookie-reference.md)；隱私權政策統一依照 [隱私權政策公版](evo-privacy-reference.md)，正文放在 `.innerpage-body`，內容與順序逐字保留，只替換公司完整名稱。版型與樣式沿用公版，已有本案 `:root` 變數的字型、字級、色彩與間距必須接本案變數，維持當下網站一致性。「隱私權政策」文字必須連到本案實際可開啟、有內容的政策頁面，不使用空連結或占位頁。

EVO 選單、root、漢堡、按鈕與語系以使用者指定的 [evo266200 Header 參考](evo-header-reference.md) 為工程依據；製作相關元件前必讀其結構、變數、狀態與來源限制，再依本案首頁調整樣式。

內頁麵包屑以 [evo263525 breadcrumb001 參考](evo-breadcrumb-reference.md) 為工程依據，保留其語意結構、class、data 屬性與目前頁標示，集中管理內頁共用樣式。

舊平台流程的案件都要完成搜尋結果頁，與共用 Header／Footer、Cookie 提示及隱私權政策頁一起納入首次網站製作的頁面清單。結構統一依 [evo266200 搜尋頁指定參考](evo-search-reference.md)，製作前必讀；搜尋入口必須連到本案搜尋頁，不能只有按鈕或空連結。搜尋頁公版 HTML／JS 不修改，CSS 以指定系統共用頁為基準，可依案件確認需求調整，未指定調整時忠實沿用參考；本案共用 Header／Footer 與系統 CSS 已有變數仍沿用。正式搜尋資料由本案平台提供。此系統頁例外優先於下方一般內頁風格規則。

FAQ 一律沿用 [evo266125 系統範本結構](evo-faq-reference.md)：HTML 層級、標籤、class 與 data 屬性固定，CSS／SCSS 外觀可依案件調整。此為使用者明確指定，不受本檔開頭的舊流程限定。

**舊流程的執行時載入方式**：首內頁在對應位置使用以下共用載入容器，每頁各一個；整站 HTML 不採此方式，建置時將共用來源輸出到每頁 HTML，必要直接子層與標記依工程師套件，不用空殼或 fetch 補齊：

```html
<div id="site-header" aria-busy="true"></div>
<!-- 本頁主要內容 -->
<div id="site-footer" aria-busy="true"></div>
```

- Header 與 Footer 各維護一份共用 HTML，由共用 JavaScript 載入；不要在各頁複製整份內容。共用 Navi HTML 使用 `<header>`，Footer 使用 `<footer>`，不重複放上述容器 ID；`<header>` 僅允許此全站 Navi 使用，其他區塊改用 `<div>` 等容器。
- 優先沿用前端工程師提供的切版基底之共用檔案位置、載入方式及初始化流程；基底未附時由 實作端 補齊並記錄路徑，不宣稱 clone 後已具備載入功能。
- 各容器內容載入成功後設定 `aria-busy="false"`，再初始化導覽、手機選單及相關互動，避免重複綁定。載入失敗需結束忙碌狀態並回報可辨識錯誤，不將空容器當成完成。
- 透過本機預覽伺服器驗證；確認首頁及不同目錄深度的內頁都能載入共用內容，Logo、圖片及導覽連結路徑正確。共用樣式沿用既有 Header／Footer SCSS 與 Common 架構。
- 實作端 品檢確認：修改共用內容會同步反映於首內頁、載入完成後容器不再忙碌、本輪範圍內的桌機／平板／手機選單正常，且沒有載入失敗或重複初始化錯誤。

- Header／Footer 依已確認設計實際製作並填入本案 Logo、選單、語系（如有）、連結、聯絡資料與頁尾內容，載入後提供完整可操作內容。
- 頁尾版權列只能保留以下完整 HTML（2026-10-05 使用者指定），**寫死、不因案件或已確認設計跟著改**；包含外層 `.copyright-bar`，結構、文字與連結逐字沿用，樣式可依案件 Footer 配色調整。不得另外加入 `copyright-owner`、`©`、年份、客戶公司版權文字、Copyright 或 All Rights Reserved，也不以 JavaScript 自動補上。既有頁尾若有這類額外版權內容，在處理該頁尾時移除，保留其他聯絡及公司資訊：

  ```html
  <div class="copyright-bar">
    <div class="copyright-text">Designed by<a href="https://www.webtech.com.tw/" target="_blank" class="copyright-link">米洛科技有限公司</a></div>
  </div>
  ```
- 首內頁共用一致風格與操作；需要更改已確認設計時列原因及影響，交使用者確認。不啟動角色交接或自行搜尋新母版。
- EVO 已有適用範本的功能（例如選單、分類、列表），優先沿用現有範本結構，再依目前首頁設計調整字型、色彩、尺寸與間距，不重新發明結構。先找本案既有元件、開發提供的範本，或使用者提供的既有網站案例；核對 HTML 層級、必要 class／ID／data 屬性、初始化與操作狀態，保留轉 EVO 所需的對應。記錄範本名稱／編號、來源、工程版本及可調整範圍，不搬用其他客戶素材。
- 既有案例與本案 EVO 版本不相容時，依本案開發規格修正必要差異並記錄原因，不直接照搬不適用的舊綁定，也不以版本不同為由整份重寫。缺少範本原始碼或新版整合資料時，先查可用來源並標出缺口；不能只憑截圖自造結構後宣稱可直接轉 EVO。此規則限於 EVO 已有範本的功能，不限制本案自訂創意區塊的構圖。
- 單純文章編輯器內容區可使用簡單 HTML／CSS 編排，不強制套系統列表版型；仍沿用首頁字型、色彩、間距、按鈕及品牌。關於我們、ESG、服務等核心頁依本案已確認設計維持首頁完成度；列表、下載、文章與表單以閱讀及操作穩定為主。不能因稱為內頁就簡化已確認的構圖或動態。
- 只有版型名稱或截圖，不能推定新版系統的資料綁定、初始化方式或後台整合規格。缺資料只標受影響功能整合後待驗，不把預覽完成當成後台整合通過。

## 可增減或排序的內容

凡可新增、刪除或排序的內容，版面與互動都須依實際項目呈現。這項原則適用於所有頁型和元件，例如頁籤、分類錨點、列表、卡片、輪播、相簿、FAQ 與規格表，也適用於靜態切版與 EVO 頁面。

- 零筆時，依設計隱藏區塊或顯示空狀態，同步處理指向該區塊的控制或錨點。只有一筆時，保留內容並省略無作用的切換控制。
- 保留設計指定的欄數與排列方式。固定欄數的品牌牆可自然換行，等寬頁籤則按實際項目數分配。項目增減時應能沿用原版型。
- 標題、內容、連結與選取狀態使用明確且穩定的資料對應，例如項目 ID。新增、刪除或排序後，仍須指向正確項目。若目前選取的項目被刪除，依元件設計回到有效項目或空狀態。

驗收依 [可增減或排序的內容檢核](implementation-review.md#可增減或排序的內容檢核)。系統元件的 HTML、JS 與資料標記仍遵循本案平台契約。

## 多層分類的共用列表頁設計

EVO 有兩層或更多層分類、下層沿用同一列表版面時，分類列表的共用頁面設計放在這組分類最上層的選單節點，下層分類沿用該版面並顯示各自的資料。這裡的「最上層」是該組分類的共同上層，不是網站首頁。

例如「立即購買 → 刺繡貼紙／刺繡吊飾／LINE 貼圖」：共用側欄、列表排列與主列表替換區由「立即購買」這一層維護；各子分類不重複放一份完整頁面設計。商品、文章與分類專屬內容仍屬於各自分類，不因共用版面而搬到上層。

- 切版與交接須標明共用列表設計所屬的上層節點，以及哪些子分類沿用；主列表替換區依下節標記。
- 「分類列表頁設計」與「內容頁版型」分開處理；後者是點進單筆商品／文章後的版面，不能拿它代替列表頁設計。
- 若已確認某個子分類需要獨立版面，保留該例外，不強制覆蓋成上層設計。
- 後台操作前核對實際編輯目標：群組採「直接進入第一個子項目」時，畫面上的「頁面設計」可能開啟第一個子分類。依介面提示確認設計實際存放的節點，不只憑目前選中的群組名稱判斷。

## 列表頁與內容頁的替換範圍

先依本案交付方式選擇下列流程。兩者都沿用已確認的卡片樣式與響應式版面。獨立商品或文章內頁若另有動態列表，依該列表的用途與本案流程製作。

新站在切版時就依選定的匯入方式，把所需的 `data` 標記寫進實際交付的 HTML。若商品內頁要沿用列表外框，從一開始就把 Banner、麵包屑和側欄安排在共用外框，劃清列表卡片與分頁所在的區域，以及商品詳情要接入的位置。後台做版／Project JSON 依目標站的原生替換邊界設定；整站 HTML 依本案 `evomni-html` 套件確認支援方式，未確認的外框繼承列為待確認。

發布後從正式前台列表點進至少一筆商品，確認 Banner、麵包屑和側欄仍在，原列表卡片與分頁已換成該筆商品的一份詳情。無法開啟正式前台時，將這項驗收列為待驗。

### 後台做版／Project JSON

**製作與交付**

1. 在目標站後台沿用「基本 → 列表區塊」，將商品或文章主列表與其分頁放在同一區塊。側欄、頁首標題、麵包屑及其他共用外框放在區塊外。
2. 內容頁沿用列表頁外框時，在同一個主列表 `<div>` 保留兩個屬性，完整寫法為 `<div data-list-group-container="true" data-replace="detail-content">`。沿用已有標記的容器，校稿時檢查屬性成對、同層，並排除重複巢狀的替換容器。獨立內容頁依自己的版型製作。
3. 交付 Project JSON 時，以目標站匯出的原生元件核對 `list-group` 組件類型、分頁結構與內容頁繼承設定。缺少匯出樣本時，將原生結構與設定列為待核對。

**儲存或匯入後驗收**

1. 重開後台畫布，確認 EVO 原生藍色虛線框與「主列表區」提示涵蓋實際列表及分頁，共用外框位於區塊外。以 EVO 畫布實際顯示的框線為準，禁止用 CSS 畫框代替。選取「商品列表」，確認可設定「每頁商品數量」。
2. 有分頁時，用足以形成兩頁的資料測前台。第二頁應換一批內容，全頁只有一組有效分頁。
3. 有共用外框時，點卡片確認只替換主列表區，側欄與其他共用區仍在。返回列表再確認列表與分頁正常。

#### 案例｜自造盒子商品內頁沿用列表外框

本案在商品列表頁開啟「內頁沿用本頁外框」。Banner、麵包屑和側欄放在原生藍色虛線框外，商品卡片和分頁放在框內。前台點進商品後，框內整區換成該筆商品的詳情。藍框由列表頁畫布產生，單品畫布只放商品詳情。

**失效原因**

- 舊商品 Project JSON 帶有 `data-mudobox-product-page="full"`。自造盒子的客製程式讀到這個設定就優先走獨立商品頁，即使列表頁已開啟外框繼承。
- 單品畫布只顯示商品內容時，當時前台的 Banner 和側欄由「共用內容頁版型」補上。清空共用版型後，商品內容仍在，Banner 和側欄也隨共用版型消失。
- 這個站的舊流程會帶入側欄內容，該版型的 CSS 卻未一起載入正式站，因此後台畫布看起來正常，正式站仍可能跑版。

**修正方式**

1. 確認列表頁已發布並開啟「內頁沿用本頁外框」。原生「列表區塊」用同一個容器保留 `data-list-group-container="true"` 和 `data-replace="detail-content"`，並核對框內外的內容。
2. 匯出一筆商品的原始 Project JSON 並保留備份。用其副本移除本案觸發獨立頁的設定與單品整頁外框，保留商品圖庫、價格、說明、規格、影片、詢問車、原有欄位綁定與商品互動。
3. 核對列表外框與商品詳情合併後的互動初始化。側欄下拉和商品頁籤各初始化一次，避免重複產生控制項或重複綁定操作。合併後維持一個 H1，本案保留列表 Banner 的 H1，商品名稱使用 H2。
4. 將修正版匯回同一筆商品的「頁面設計」，先發布並驗收這一筆，再逐筆套用。其他案件先從目標站的繼承設定、實際輸出和樣式載入找原因。本案的客製屬性與移除方式只適用自造盒子。

**正式站驗收**

1. 從已發布的正式站列表點進測試商品。對照後台繼承設定、列表頁畫布與正式站 HTML，確認 Banner、麵包屑及側欄沿用列表外框，原卡片與分頁已被一份正確的商品詳情取代，整頁只有一個 H1。
2. 桌機確認側欄版面，並核對相關 CSS 在正式站有載入。手機實際操作分類下拉，確認只有一組控制項。逐一操作商品圖庫、頁籤、影片與詢問車，確認功能及資料正確。
3. 分別記錄畫布／即時預覽與正式站的結果。無法進入正式站時，逐項列出外框來源、替換範圍、CSS 與互動的待驗項目。

### 整站 HTML 匯入

**製作與交付**

1. 依 [EVO 範本查核](evo-preflight.md) 讀取本案 `evomni-html` 套件，依其列表頁、卡片及單筆內容頁規範完成 HTML。商品或文章卡片連到同一組資料的對應內容頁，每筆資料各有自己的內容頁 HTML。分類卡片及共用外框依套件與本案設計安排。
2. 需要翻頁時，依套件規範標示每頁筆數及分頁，讓 EVO 產生翻頁結果。若採套件支援的文章原地展開，依該模式準備展開內容並省略分頁。後台做版的替換屬性和 Project JSON 僅在對應交付流程檢查。
3. 依本案套件執行檢查與交付驗證，記錄套件版本、預檢結果及匯入模式。

**匯入後驗收**

1. 在後台確認列表接到正確的商品或文章資料與分類，內容頁及本案需開放編輯的欄位可從對應入口操作。前台比對卡片資料、連結、共用區及本案尺寸下的版面。
2. 有分頁時，以足以形成兩頁的資料測每頁筆數、第二頁換資料及全頁只有一組有效分頁。只有一頁時確認翻頁控制依套件規則隱藏。
3. 一般列表點卡片後應開啟正確的單筆內容頁。若本案已確認內容頁共用列表外框，再核對側欄等共用區仍在，且只變更指定的內容區。文章原地展開則測試點卡片展開正確文章，以及本案設定的分享連結或轉址能開啟對應文章。

**驗收紀錄**

在工程師交接說明逐項記錄本案流程、已實測結果與待驗項目。缺目標站後台時，依流程列明待驗的畫布框線、設定、資料對應或編輯入口。缺前台或測試資料時，列出受影響的翻頁、內容頁或原地展開項目。可獨立執行的前台驗收照常做。依本案設計省略的功能標記為不適用。

## 全站導覽行為
