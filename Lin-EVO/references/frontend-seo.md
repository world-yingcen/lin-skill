# Lin-EVO｜切版端 SEO 責任

適用首頁、各內頁、搜尋頁與其他系統頁面的實作及校稿。局部修正檢查受影響頁面與共用項目，未授權的全站整改列待辦；完整網站交付則逐頁完成。不因 SEO 修改已確認文案、品牌設計、案件範圍或擅自新增後台功能。

**公司內部規定：每個完整頁面有且只有一個 h1，h2～h6 依內容層級安排，不向下跳級。** 這是公司製作與驗收約定，不寫成「Google 規定多個 h1 就扣排名」。Google 沒有規定理想標題數量；清楚的內容組織與語意仍須維護。詳細標題規則依 [T04](html-css-rules.md#t04html命名與語意)。

## 每頁製作責任

| 項目 | 切版端必須完成 |
|---|---|
| 頁面主題與可讀內容 | 主題、主標題與正文一致；保留已確認文案、分段與必要資訊。不堆砌關鍵字、不新增未證實宣稱。重要標題與資訊保留真實 HTML 文字，不只做在圖片、偽元素或 canvas 裡；動畫或套件失敗仍能閱讀。 |
| title | 每頁設定清楚且能區分內容的 `<title>`，一般以「本頁主題｜品牌名稱」組成；整站 HTML 若由系統附加品牌，依當次工程師規範只填頁名，不重複追加。不整站只用同一公司名，也不殘留其他案或預設範本文字。正式文案未確認時標記草稿。 |
| meta description | 每頁設定符合實際內容的簡短摘要，不整站複製相同描述、不填與內容無關的關鍵字。沒有公司既定字數時不把固定字數寫成 Google 要求；搜尋摘要可能由 Google 另行選取正文，不能保證照 meta 顯示。 |
| heading 與語意 | 執行內部單一 h1 與標題層級規定。標籤由內容角色決定，外觀由 CSS 控制；heading 不用作裝飾。全站只有 Navi 可用 header，依既有 Lin-EVO 規則。 |
| 圖片資訊 | 有內容意義的圖片使用 img／picture 與描述性 alt；裝飾圖片 alt=""，不重複唸出相鄰資訊或堆關鍵字。圖片連結與 Logo 的替代文字需說明目的。確認圖片存在、裁切與內容相符，重要資訊不只放背景圖。 |
| 圖片尺寸與載入 | 設定正確 width／height 或預留比例，降低載入跳動；依顯示尺寸提供適當解析度，既有工程需要時使用 srcset／sizes。首屏主要圖片不一律 lazy loading，其餘圖片依用途延遲載入；不每張圖都 preload。容量及非 WebP／SVG 提醒依 [圖片檢核](implementation-review.md#切版完成後的容量與圖片格式檢核)，由使用者自行轉檔，Claude 不代為處理。 |
| 連結與導覽 | 頁面／外部網址使用有真實 href 的 a，按鈕處理操作；不可只靠 onclick 假裝頁面連結。連結文字或可存取名稱能辨識目的；一般連結不留下 #、javascript:、空 href、localhost、其他案或測試站連結作正式目標；工程師套件明定由系統產生網址的標記及占位形式為局部例外，依契約保留並列正式待驗，不補造路由以通過一般檢查。靜態預覽使用實際可開啟的本案路徑；正式網址未知時列工程師待對應，不猜網址。 |
| 載入與操作效能 | 保留完整可讀內容與本案範圍內的 RWD；預留圖片／字型／非同步區塊空間，避免版面跳動。不為動畫、背景影片或第三方套件增加無用途的載入；依既有 Lin-EVO 的初始化、清理、resize 與減少動態規範實作，檢查內容及操作不被覆蓋。 |

## 正式站與工程師的核對邊界

- 切版端保留校稿站 noindex，不因完成 SEO 清單就自行解除；正式站需要索引的頁面，上線時由工程師核對並移除不適用的 noindex。robots.txt 阻擋爬取不等於禁止索引，也不能讓爬蟲讀到被阻擋頁面的 noindex。
- canonical、正式 URL／轉址、HTTP 狀態、sitemap、robots.txt、語系 hreflang、結構化資料與 Search Console 由本案平台／工程師核對。切版端整理所需頁面、內容與未定欄位，已有平台設定就保留，不自行猜正式網域、替每頁加同一首頁 canonical 或填不存在的商品評價。
- 本地預覽通過不代表正式站已能被索引、後台輸出的 title／h1 正確或搜尋排名已改善；交付時分開記錄。

## 逐頁校稿與交付

在共用元件與 JS 載入後，依實際頁面及本案授權尺寸檢查：title、meta description、h1 數量與 h2～h6 大綱、必要文字、圖片 alt／尺寸／載入、內外連結與導覽、缺檔／console 錯誤及動畫失敗時的可讀性。本案使用系統固定頁時沿用已核對的系統結構，不為 SEO 自行重做搜尋版型。

沿用既有頁面交付表，每頁記「已檢查／待修正／待確認／未驗證」及原因，不另建立內容重複的 SEO 文件。缺 metadata、缺 h1／多 h1、標題向下跳級、必要 alt 缺漏、假連結、圖片缺檔或重要內容不可讀時，先修正再驗；沒有真實內容或正式路由時列明缺口，不填假資料湊通過。

可用環境以 PageSpeed Insights／Lighthouse 等工具量測載入、操作及版面穩定性，記錄頁面、裝置條件與結果；Google 的體驗目標為 LCP 約 2.5 秒內、INP 約 200 毫秒內、CLS 約 0.1 以下。工具的實驗室結果不冒充真實使用者的 INP／Core Web Vitals 資料，也不以單一分數保證排名；沒有量測條件就標效能待驗。

## 依據

- [Google SEO 入門指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)：內容、title、摘要、圖片、連結與標題相關說明。
- [Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals)：載入、互動與版面穩定性。
- [noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing)：索引限制與 robots.txt 的區別。
