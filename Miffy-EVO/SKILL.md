# Miffy-EVO｜靜態頁面轉 EVO 後台

以已完成的靜態網站為基準，完成本案 EVO 版本支援的轉換與交付。使用繁體中文及台灣用語；由 AI 判斷技術對應，設計師確認畫面與操作，不要求設計師填寫技術標記或管理 JSON。

## 接續既有成果

- 先核對是否已成功匯入 EVO。**已轉 EVO 的案件，原靜態 Git 專案視同廢棄，只保留查閱；任何修改請至 EVO，不再修改或 push 原 Git。** 先取得目前 EVO 站台、頁面與資料狀態；需要程式修正時依平台支援的現行編輯／匯出流程處理，不能拿舊 Git 覆蓋後台新內容。只有產出 ZIP 或預檢通過，仍不算匯入完成。
- 首次轉換前需要取得 Git 切版檔時，沒有專案才 Clone；已有專案直接開啟，不重複初始化。每輪檢查 repo、分支、未提交修改及 upstream，fetch 該遠端後比較 ahead／behind。乾淨、僅落後時以 `git merge --ff-only @{upstream}` 更新；分歧、有本機修改或缺權限時保留現況並列出差異／缺口。不能只憑 VSCode 左下角沒數字就稱已同步；沒有工具則先詢問是否需要帶著操作。
- 先讀案件進度、Git 修改、指定頁面與其 HTML、SCSS、CSS、JavaScript、共用元件和素材。找出實際編譯及預覽入口，不重新開案或重做設計。
- 確認來源頁面、目標 EVO 版本、工程工具位置及輸出位置。能從案件資料取得就直接使用；缺資料只詢問會影響下一步的項目。未提供輸出位置時在案件內使用獨立的 `evo-export/`，不覆蓋已有成果。
- 區分「準備匯入包」與「操作後台匯入」。請求轉換可直接完成本機轉換、檢查與打包；實際後台匯入、上傳或發布依本次授權，已有明確授權不重問。建立此 Skill 不代表已執行任何案件的轉換。

## 先判斷流程與資料狀態

- **整站 HTML 匯入**：新的整站任務優先核對目標後台是否支援此入口，接續下方工程師套件與 HTML 流程；未確認時可準備來源，不能宣稱目標已支援。只修改局部時保留既有站台資料夾，不把單頁片段當成整站包。
- **既有 JSON 匯入**：案件明確採 `project-data.json`／evomni-page-composer 時，直接讀 [既有 JSON 流程](references/legacy-workflow.md)，依其要求更新工程庫；不要求先取得 evomni-html。沿用原流程，不自行遷移。
- **尚未確定入口**：先由案件紀錄與實際後台資訊判斷；仍缺必要資訊時列出具體缺口，完成不受影響的盤點，不靠產物副檔名猜目標能力。
- 整站 HTML 另分「首次匯入資料」「既有後台資料換版」「已匯入網站續改」。先記錄本次哪些是設計、哪些是內容更新，再依目前套件的相應流程執行；舊站重畫需要它指定的 site context 與來源畫面。既有資料換版時，套件若不更新文章／產品、選單、表單或 SEO，這些需求列為後台另行處理，不能說修改 HTML 就會同步資料。

## 工程師套件：人工更新、每次重讀

整站 HTML 匯入先沿用案件交接紀錄指定的套件；未指定時使用本 Skill 內的 [evomni-html/SKILL.md](evomni-html/SKILL.md)。工程師套件獨立維護；本 Skill 只負責定位與使用，不複製其欄位、標記、檢查及打包規則，也不鎖定版本號。

### 設計師下次收到新版時

1. 依目前工具的 Miffy-EVO 安裝紀錄核對來源與連結／複製模式；使用案件獨立套件時核對其實際位置。沒有紀錄時先辨明目前使用位置，不猜來源。向工程師取得新版 `evomni-html` ZIP；目前僅支援人工更新，沒有固定的最新版下載網址。
2. 先解壓到暫存位置，核對版本、完整性與新版說明，確認是使用者提供或指定的工程師包，再完整替換已確認的工程師套件位置（一般為 Miffy-EVO 來源資料夾內的 `evomni-html/`），不要混合新舊檔案。替換前保留舊套件備份於 Skill 資料夾外；若套件有自行修改，先核對差異，不直接覆蓋。
3. 確認 `evomni-html/VERSION`、`SKILL.md`、`references/`、`example-site/`、`scripts/` 都在同一層，避免多包一層資料夾。實際套件結構若改版，以新版說明為準。
4. 同步至目前工具實際使用的 Miffy-EVO：連結模式直接讀來源；複製模式須依安裝紀錄，以來源的安裝器只同步 Miffy-EVO，不必重新撰寫本 Skill。AI 有本機操作能力且來源已確認時直接完成同步並核對內容；使用 `python3 <來源>/install.py --skill Miffy-EVO --target <目前工具的 Skills 目錄>`，這次本機同步不加 `--update`（它是更新 Git 來源，人工替換後的未提交修改會使它停止）。案件獨立套件則更新其紀錄，不覆蓋其他案件。未受管理的上傳 ZIP 環境交付新包並說明需重新上傳，不假裝已同步本機安裝。

已知發行連結：[工程師提供的 1.1.0 ZIP](http://192.168.168.99/shared-resources/html-skills/evomni-html-1.1.0.zip)（限內網）。這只是該版的取得紀錄，不是最新版端點；不可猜下一版網址、反覆下載舊版或宣稱已自動檢查更新。舊 `site-html-import.zip` 已停用，不作為轉換依據；使用者若要求清理，再核對實際檔案處理。

### AI 每次轉換或校稿前

- 從目前實際使用的套件重新讀取 `VERSION` 與 `SKILL.md`，寫入或調整 HTML 前完整讀取其 `references/spec.md`，並依套件指示讀本輪其他 references；檢查工具與規範必須來自同一份套件，不能只憑上次對話、摘要或記憶執行。
- 回報「目前使用 evomni-html <VERSION 實際值>，由人工更新；未自動確認最新版」，並在案件交付紀錄留下套件位置與版本。若使用者已提供新版，先完成上述替換與同步再執行。
- Lin 與 Miffy 同一案使用相同的套件位置與版本。若來源、安裝副本或案件紀錄不一致，先核對差異與是否已完成同步，不靜默換用另一份；工作途中不更換套件。下一輪人工更新後，比對規範影響並用新版工具重驗交付範圍。
- 缺套件、VERSION 或必要工具時，列出具體缺檔，先做不受影響的盤點；不自行補造工程師規範、檢查紀錄或可匯入宣稱。

## 整站 HTML 的執行順序

1. 讀取本案的 Lin 交接、客戶確認範圍與實際來源；涉及來源修正時讀 Lin-EVO 相應規範。匯入契約依本次工程師套件，套件不支援的需求提出具體影響與方案，不無聲刪掉功能或改設計。
2. 沿用已完成的頁型、共用結構、欄位與資源安排；補缺及修正錯誤即可，不重做設計、全站格式化或重啟開案。已匯入案件以目前 EVO 內容為準，保留檔名與內容識別；需要重新匯入時先確認現行來源與本次換版授權，不使用已廢棄的原靜態 Git 當有效來源。
3. 編譯並將本次交付所需 HTML、CSS、JS、素材輸出到獨立的暫存／交付目錄；沿用可重現的建置，不手工維護第二份網站。保留原始素材與歷次交付，排除工具庫、備份、Git、環境設定及無關檔案。確認套件要求的頁面與依賴齊全，不為缺頁捏造客戶內容。
4. 在實際交付目錄執行同一套件的檢查工具，修正錯誤並逐項處理警告，再驗靜態畫面與操作。檢查紀錄須由工具產生，版本需與套件 VERSION 一致；若不一致，先查是否新舊檔案混合。最後一次修改、換圖、改路徑或編譯後必須重驗，不能直接沿用 Lin 較早的檢查紀錄。
5. 依當次工程師規範打包並核對 ZIP 實際內容、資源引用及檢查紀錄。包與檢查報告必須對應同一份輸出，ZIP 放在被打包目錄外，避免將自己或舊包包入。Node／檢查工具不可用時依工程師替代檢查流程處理，成果只標「待後台預檢」，不偽造紀錄或稱已驗證可交付。
6. 更新本案唯一的 `工程師交接說明.md`，交付包、結果與正確後台入口。實際上傳、匯入、發布依已取得的授權；匯入前核對預檢所列頁面／資料對應及變更，超出本次範圍先處理，不以本機檢查通過代替確認目標。
7. 請使用者開啟本案 EVO 後台的「整站匯入」，上傳本次 ZIP；有已授權的後台工具才代為操作。將程式回報的錯誤帶回 Claude，由 Miffy 修復、重驗及重打包，再上傳，直到本次報告為 0 錯誤。不得降低檢查、偽造報告或忽略警告；遇到平台缺陷、權限或範圍問題，列出阻礙交工程師處理，不反覆上傳相同包。
8. 實際匯入成功後逐頁檢查畫面、素材、連結、互動、RWD 及內容編輯／儲存；發布後前台另依授權驗證。在交接記錄 EVO 站台與匯入版本，標記後續改至 EVO、原靜態 Git 停用。未測項目明列，不以 0 錯誤代替畫面與功能驗收。

## 離開前交接

沿用唯一交接紀錄，留下目前階段、來源／輸出與 ZIP 位置、套件版本、檢查結果、EVO 站台、已完成及待辦。尚未匯入且仍在 Git 切版階段，換電腦前依 Lin-EVO 的交接流程確認範圍後 commit 並 push，成功才算完成；另一台取得同一版本並由 Claude 先讀交接再繼續。已匯入 EVO 的案件改核對後台儲存與案件交接，不為換電腦推送已停用的原 Git。缺工具或權限時列待完成，不宣稱已同步。

## 共用的保留與驗收原則

- 原始網站與確認基準保留，修正在有效來源，再重新建置與驗證。HTML 與 JSON 兩條流程的 schema、工具、載入及打包方式不互相套用。
- 共用／單頁樣式保持來源對應、載入順序與原本 media 條件；動畫讀取最新內容，暫時拆字、輪播副本與執行中狀態不存回原始內容。具體畫布與前台處理由本案契約決定。
- 圖片處理沿用案件已確認分工；工程師套件要求縮圖或容量超限時，先核對是否已授權 AI 處理，未授權則列待提供合格素材，不擅自改畫質或以改副檔名充當轉檔。圖片、字型、影片及連結可追溯來源與正式位置，不搬用他案媒體 ID、實例 ID 或測試站路徑。套件文件與檢查器有差異時，記下版本、檔案與重現結果；不手改工程師套件或降低檢查來宣稱成功，受影響部分列待工程師釐清。
- 依 [轉換與驗收檢查](references/conversion-checklist.md) 驗實際範圍：本機結構／工具、靜態視覺／操作、後台編輯／儲存、發布後前台分開記錄；缺後台存取不阻止完成本機交付，但不宣稱已匯入或驗收。
- 在同一份交接文件記錄流程、資料狀態、來源與輸出、套件位置／版本、重現命令、素材、可編輯項目、差異與未驗證範圍；已有 Lin 文件就接續更新，不再建立重複說明。保留已完成的客戶確認，新差異才需重新核對。
- 完成後簡短告知成果位置、正確入口、已測範圍與後續待辦。準備匯入包不自動授權外部操作。
