# LIN｜切版完成後的工程師交接說明

切版完成後，AI 必須依實際 HTML、SCSS／CSS、JS、素材、預覽及驗證結果建立或更新 **`工程師交接說明.md`**，讓工程師知道哪些已完成、哪些需要接入，以及功能面要注意什麼。不要求設計師手填，也不以聊天回覆或只有程式清單代替交接文件。

## 位置與維護

- 每案只保留一份有效正本，放在案件既定交付目錄；沒有約定時放專案根目錄。README 與進度檔連到正本，文件及其內容使用專案相對路徑，不寫維護者電腦的絕對路徑。
- 既有交接文件先整理為此正本，保留必要紀錄；其他文件引用它，不另外建立相同的功能說明、JS 交接表或版本副本。已有專門規格與技術證據可連結，不整份複製。
- 首頁、內頁或本輪授權切版範圍完成就更新，標明實際範圍，不等全部頁面都完成。後續改動功能、檔案路徑、套件、素材、初始化或後台可編輯需求時同步更新；純文字小修影響功能說明時也回填。
- 文件記更新日、目前成果版本／確認狀態與預覽方式，不能只用檔名或「最終版」代表客戶已確認。

## 必備內容

| 內容 | 工程師需要知道的資訊 |
|---|---|
| 目前入口與製作範圍 | 預覽／啟動方式、交付版本、已完成頁面、本輪尺寸與 RWD 範圍、已確認與尚未確認項目。 |
| 頁面與資源對照 | 依 [頁面對照表](evo-preflight.md#交付頁面對照表) 列各頁 HTML、SCSS → CSS、專屬 JS、共用依賴、套件版本、互動與可編輯項目。列資源載入順序與編譯方式；沒有專屬 JS 填無，不造空檔。 |
| 功能接入注意事項 | 每個實際使用功能列「所在頁面／區塊、操作行為、實際程式／初始化位置、必要 class／id／data、依賴與啟動時機、工程師需接的部分」。包含本案已有的搜尋、表單、輪播、燈箱、導覽、捲動動畫等，不為補文件新增功能。 |
| 後台可編輯需求 | 哪些文字／圖片／清單可修改、增刪、排序，內容來自平台資料還是頁面本身，已實作的標記與契約來源；哪些尚未核對。動態需跟隨新內容、重新初始化或清理的地方明列，不宣稱僅寫標記就已可後台編輯。 |
| 待串接與功能差異 | 靜態示範資料、正式路由／API／表單送出、媒體入庫、套件啟用、初始化接入及未支援契約，依實際需求列出。未知值寫待確認，不猜 API、平台事件、正式網域或欄位。 |
| 驗收與已知問題 | 按頁面／功能列靜態已測、客戶確認、工程師待接入及正式後台／前台待驗；附實際版本、尺寸與證據位置。列已知缺陷、待補資料、影響及下一步，不把未測項目寫成通過。 |

## 功能面必須說清楚

- 搜尋：入口、keyword 參數與結果頁、系統固定樣式、靜態示範與正式搜尋資料的差別，空結果／無圖等已測狀態。
- 表單：已做的欄位與前端檢核、實際送出流程是否接好；未串接時不可顯示假的寄送成功。正式資料欄位與送出端點只記已確認的值。
- 輪播／燈箱／動畫：使用版本、實例與初始化位置、共用或單頁責任、resize／內容更新／清理及減少動態。套件宣告、載入與初始化分開記錄，依 [EVO vendor 契約](evo-vendor-libraries.md) 列 data-vendor 或編輯器工具列開關；Lenis 是否已部署、正式前台是否已測不能省略。
- 平台接入與 SEO：列正式連結、title／描述、單一 h1、索引／canonical 等已做與工程師待核對項目，依 [切版端 SEO 責任](frontend-seo.md) 分工；記錄套後台後可能改變 DOM／標題的地方。

## 交付前核對

AI 重新比對文件與目前實際檔案／行為：相對路徑有效，編譯與載入關係正確，沒有已移除功能、舊入口、漏列的套件或「已完成」但未串接的項目。文件缺漏先補，已知程式缺陷依本輪授權修正；依賴工程師或缺環境的項目明列待辦。

完成回報必須提供 `工程師交接說明.md` 的實際位置，以及最重要的待接入／待驗事項。**文件完成不代表平台匯入、資料串接、部署或正式驗收已完成**；本規範也不授權自動執行這些外部操作。
