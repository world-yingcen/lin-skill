# LIN｜實作與校稿

## 工程與修改範圍

- 盤點實際編譯、匯入、預覽與 Git 狀態，保留未提交修改。沿用既有版本與工程入口，不強制把 @import 改為 @use。
- Common 只有一份有效來源；不另造 `_common.source.scss`。保留有用途的空檔／資料夾，空檔不代表已完成。確認編譯出非空 CSS 且頁面實際載入，不手改編譯產物。
- 新基底記來源版本，不覆蓋既有案件或回寫來源庫；不擅自移除巢狀 Git。套件、Git、發布及部署依本案授權，純切版規範不構成外部操作授權。
- 靜態原型與既有框架沿用各自工程路徑，不強制搬到特定編號資料夾。首頁與交付範圍內頁須有實際可瀏覽入口。
- 文案、正式 Logo、產品、IP 及品牌規範依確認版本保留；缺素材不能默默替換。生成情境不能冒充真實推薦、顧客或成效。

## 系統檔案與 Git 追蹤

- 建立或接續 Git 專案時，確認 repo 根目錄 `.gitignore` 有獨立一行 `.DS_Store`；規則適用所有子目錄。只補缺少的項目，不覆蓋既有忽略規則，不修改使用者全域 Git 設定。
- `.gitignore` 不會解除已追蹤檔案。先以 `git ls-files -- '.DS_Store' '**/.DS_Store'` 檢查；有結果時逐筆以 `git rm --cached -- <實際路徑>` 移出追蹤，保留本機檔案。不清除整個 repo 的追蹤索引，也不因此自行提交或推送。
- 提交前確認 `.DS_Store` 未被新增；移出追蹤與忽略規則隨本次已授權提交處理。交付清單與分享包也排除 `.DS_Store`。

## 視覺還原與閱讀

以同尺寸設計稿／來源畫面比較容器寬、區塊高度、padding、margin、gap、字級、行高、字重、換行、圖文比例、留白、圓角與陰影。明顯差異先查 CSS cascade、排版結構及字型實際載入，不只微調數值。

核對原文分段、標題階層、必要資訊及 CTA。圖片實看主體、比例與 object-fit 裁切，動態最大位移不露底、不切掉重要人物／產品。資料變長時合理延展，不能靠固定高度裁掉文字。

設計稿缺少 responsive 時依原本資訊層級與構圖合理延伸；尺寸以案件斷點及內容決定，沒有公司定案的尺寸／容差不寫成固定規定。桌機限定任務只報告該範圍；既有響應式保留。

## 動態與操作

依本案功能測試正向／反向捲動、重進、快速捲動、resize、重新載入及深連結。文字在穩定狀態可讀，CTA 可操作，不為裝飾動態強制等待。釘選舞台與下一段交接不跳版、不留失控空白。

實際測試 hover、Tab／focus-visible、按鈕、導覽與回頂部；RWD 在範圍內時測觸控與手機導覽。減少動態仍保持完整資訊與操作。檢查 overlay／pointer-events、焦點及錨點是否被固定導覽遮住。

使用現有工具檢查 console、必要資源載入與相關 JS 語法；數值 FPS 或延遲宣稱需有量測條件與證據，不能從「看起來順」推算。

## 切版完成後的容量與圖片格式檢核

- 首頁、內頁或整案切版完成回報時，主動請使用者檢核專案檔案大小，確認實際交付／網站載入的檔案容量及個別圖片大小；原始素材與歸檔容量分開說明，不混成網站載入量。
- Skill 只用檔案清單、附檔名與大小盤點，不為容量檢核載入圖片內容。發現網站使用的圖片不是 `.webp` 或 `.svg`（不分大小寫，如 JPG、JPEG、PNG、GIF）時，列出檔名、相對路徑及大小，提醒：「請檢核專案檔案大小；以下圖片尚非 WebP／SVG，請自行轉成適合網頁的格式後提供。」原始設計檔與歸檔素材只列用途，不要求全部轉檔。
- 為避免額外 token 消耗，**Claude 不代為轉檔、壓縮或批次處理圖片，也不轉交其他代理繞過此分工**；由使用者自行處理。照片通常轉 WebP，向量圖使用 SVG；不把照片硬轉 SVG，不以改副檔名代替轉檔。WebP／SVG 仍須檢查實際容量，不能只因格式符合就宣稱是小檔。
- 記錄待使用者轉檔／容量待檢核狀態；使用者提供完成檔案後，才更新必要的 HTML、CSS、JS 圖片引用並檢查顯示、透明背景及動畫是否保留。不擅自刪除原檔，不將待處理事項記成已完成。

## 共用影響與交付

校稿時列出本輪頁面與共用檔案的所有 `<header>`，確認每一個都屬於全站 Navi／主要導覽；搜尋結果標題、內頁標題與卡片等非 Navi 區塊不得出現。不能只憑 class 名稱判斷。改成適合容器後核對樣式、標題層級及相關互動，未處理的非 Navi `<header>` 列為缺陷。

每案必核對 [搜尋頁](evo-search-reference.md)：有實際預覽入口，Header 搜尋可導向、keyword 正確保留，結果筆數／卡片／無圖及無結果狀態完整，結果區 HTML 與固定系統 CSS 一致，並以同尺寸畫面对照指定參考，不接受只有 class 相同卻另寫版型；Header／Footer 與連結使用本案版本。靜態示範與正式平台搜尋分開記錄；搜尋頁缺漏列為未完成，不因其他內頁已通過就宣稱整案完成。

交付工程師前，自動整理 [頁面對照表](evo-preflight.md#交付頁面對照表)，核對實際檔案與依賴，分開記錄靜態預覽、客戶確認、工程師轉檔與後台／前台整合狀態。

將轉 EVO 的案件，依 [EVO 範本查核](evo-preflight.md#ai-主動判斷客戶可編輯需求) 主動盤點客戶可編輯區塊，核對內容來源、逐筆結構與增刪／排序／換圖後的版面及互動；只對用途不明或影響已確認設計的區塊詢問使用者。記錄靜態模擬與後台實測的不同狀態。

對本輪涉及的項目逐項核對：Swiper 預設樣式與原生變數、AOS 區塊淡入淡出、圖片濾鏡是否必要、hover 是否依 T08 巢狀放置，以及 Header／marquee／breadcrumb／FAQ 是否沿用指定結構。頁尾版權列須只有 T13 的完整 copyright-bar，不含額外公司版權或年份。檢查實際程式與操作，不以讀過文件代替通過；未涉及的元件不新增。

- 修改前找出 Common、共用元件、JS 入口及其使用頁面。共用修改檢查所有受影響頁面的資源與必要操作，實看首頁及各受影響頁型的代表畫面。
- 頁面專屬修改檢查該頁、前後區塊及跨頁路徑；動態／高度修改重看正向與反向交接。
- EVO 內頁檢查 main 內第一層 wrapper 是否保留頁面 class，CSS／JS 是否命中實際結構，且未依賴靜態 body 的自訂 class；依 T04 核對匯入邊界，不把靜態 DOM 檢查當成正式轉檔驗證。
- 單頁隔離檢查：逐頁確認 HTML 與 CSS 匯入鏈只載入約定共用、本頁及必要套件資源，未夾帶其他頁樣式；在此條件下獨立開啟，檢查 Hero、CTA、共用元件與本案範圍內的 RWD。缺樣式時修正來源歸屬，不靠補載另一頁 CSS 解決；記錄 SCSS → CSS → HTML 對應與實測結果。
- 刪除失效樣式前查 HTML、動態 class 與 runtime 狀態；不整批清除套件 style、事件或其他元件。
- 記錄實際版本、頁面、CSS viewport、瀏覽器與測試範圍。編譯／語法通過、功能實測、視覺自查與使用者確認分開，不宣稱未做的獨立複核。
- 斷點保真驗證（RWD 已納入範圍時）：依 T07 比對來源編譯 CSS、轉檔輸出與匯入後實際前台的 media 條件及覆寫順序；每個受影響寬度斷點 B 都測 B−1px、B、B＋1px，非 px 單位依測試環境換算 CSS viewport 並記錄。以同一份代表內容核對欄數、顯示／隱藏、定位、間距與分類／Tab 操作；來源有小數或窄區間時再測相鄰區間，不以三點測試取代其他必要尺寸。輸出新增邊界或結果不一致即不通過，按 T07 回報；沒有匯入後前台存取能力就標示「整合後待驗」，不得宣稱已防住轉檔問題。
- 有已知缺陷就列出與處理建議；沒有實測的裝置、後台與功能明列未驗證。交付只保證本輪實際完成的範圍。
