# Miffy｜靜態頁面轉 EVO 後台

以已完成的靜態網站為基準，完成本案 EVO 版本支援的轉換與交付。使用繁體中文及台灣用語；由 AI 判斷技術對應，設計師確認畫面與操作，不要求設計師填寫技術標記或管理 JSON。

## 接續既有成果

- 先讀案件進度、Git 修改、指定頁面與其 HTML、SCSS、CSS、JavaScript、共用元件和素材。找出實際編譯及預覽入口，不重新開案或重做設計。
- 確認來源頁面、目標 EVO 版本、工程工具位置及輸出位置。能從案件資料取得就直接使用；缺資料只詢問會影響下一步的項目。未提供輸出位置時在案件內使用獨立的 `evo-export/`，不覆蓋已有成果。
- 區分「準備匯入包」與「操作後台匯入」。請求轉換可直接完成本機轉換、檢查與打包；實際後台匯入、上傳或發布依本次授權，已有明確授權不重問。建立此 Skill 不代表已執行任何案件的轉換。

## 轉換原則

1. **保留基準。** 原始 HTML、素材、編譯 CSS 與可操作預覽保留；可重現的中間檔與輸出放在獨立位置，不手工維護兩份互相漂移的網站。需要修正來源時採最小修改，重新編譯與轉換。
2. **依頁型分流。** 首頁、內頁、共用 Header／Footer、分類與文章內容分別核對正式匯入邊界。內頁的頁面作用域須位於可匯入內容內，不依賴匯入範圍外的 body class。平台 layout 已提供 main 時，不再嵌套第二個 main。Header／Footer 的排除、marker 或接入方式依本案契約，不一律刪掉或照搬。
3. **保留編輯需求。** 消息、產品等平台資料沿用正式資料綁定；FAQ 按指南使用 `faq001`；頁面自身重複內容按正式的 `data-repeater`／`data-rp-*` 契約補齊。詳見工程師內頁匯入規範。保留有效標記，不編造屬性、實例 ID 或媒體 ID。載入套件、逐筆編輯、畫布預覽與前台初始化分開確認。
4. **樣式不漂移。** 共用與單頁 SCSS／CSS 保留來源對應與載入順序。保留原 media 條件、單位、斷點及覆寫順序，不新增小數補償、不改成互斥區間；編輯器改寫造成差異時回報具體來源與輸出，不以改設計掩蓋問題。
5. **互動跟隨內容。** 保留 Swiper、AOS、GSAP 及既有捲動系統的版本與行為；整理正式 page-resource 的載入與初始化，避免全站功能重複建立。畫布保留完整可編輯原文，前台動畫讀取最新內容；暫時拆字、輪播副本及動畫狀態不得存回內容。畫布判斷、清理事件及平台生命週期只用本案已核對的方式。
6. **素材可追蹤。** 圖片、字型、影片與連結逐一對應來源、輸出及正式路徑，不搬用他案 ID 或測試站路徑。只有工程工具明確要求時才使用 `import.local` 等占位網址，並在正式前台驗證替換完成。

## 執行、驗證與交付

- 依本案工具完成必要的 convert／inject／validate／packaging；先確認會寫入的位置及副作用，產物不覆蓋來源或已使用的交付版本。檢查實際輸出與工具回傳結果；失敗時依錯誤定位結構、資源或工具原因，不靠重複嘗試參數碰運氣。
- 使用指定工程庫時，匯入包為 `project-data.json` 加 `assets/`，ZIP 使用 STORE（method 0）；詳見工程工具與打包規範。該工具支援 CSS 轉入 project data，不一律宣稱 CSS 必須外接或使用不存在的 `--no-css`。本案採外接 CSS 時核對載入與畫布呈現；JS 仍須依目標站台接入。遇到新版或不同目標格式，重新讀工程文件，不套用記憶中的規格。
- 先驗本機靜態來源與轉換輸出，再在可用且已授權的目標環境驗後台及前台。已完成的客戶確認可沿用；轉換造成新的視覺或操作差異才提出具體修正，不重啟整套設計確認。
- 未通過必要驗證的包不能標記為可交付。工具改寫斷點、缺素材或整合無法確認時，保留可追查成果，完成其他工作並明列阻塞與處理方案。
- 在案件既有交付文件記錄每頁來源、輸出、共用／專屬樣式與 JS、素材對應、可編輯項目、工具版本、重現命令及已知差異。分開標示「本機轉換／驗證」「靜態視覺／操作」「後台編輯／儲存」「發布後前台」，未執行就明說。
- 最後簡短告知轉了哪些頁面、成果位置、匯入及資源接入步驟、已測範圍，以及設計師或工程師還要檢查的項目。沒有後台操作證據，不說「已轉入後台」。
