# Lin-EVO＋Miffy-EVO｜設計師操作手冊

> 本機位置（2026-10-22）：[Lin-EVO](Lin-EVO/SKILL.md) 已搬回本資料夾內；[Miffy-EVO](../Miffy-EVO/SKILL.md) 仍在上一層。`skill-sources.json` 記錄實際位置，Codex／Claude 的連結依此管理。部分拆分期間，本機同步可用，舊整包 Git 更新仍暫停；下方整包更新說明僅適用完整原始配置。


更新：2026-10-20 · 適用 Codex、Claude Code 與 Claude Skills

這份手冊帶你從設計稿、網站校稿一路做到 EVO 匯入交付。你負責提供設計、素材與需求，以及確認畫面；AI 負責讀取規範、處理程式、檢查結果與整理檔案。

## 先知道：什麼時候用哪一個？

| 你現在要做的事 | 使用 |
|---|---|
| 把 Figma／設計稿做成網頁 | Lin-EVO（Lin-EVO） |
| 修改既有網頁、調整版面或互動 | Lin-EVO |
| 對照設計稿校稿與修正 | Lin-EVO |
| 已有靜態網頁，要轉成 EVO 匯入包 | Miffy-EVO |
| 匯入後畫面、圖片或互動不一致 | Miffy-EVO |

維護者可用同一安裝器管理 Lin-EVO 與 Miffy-EVO，但兩者可由不同 Git repo 提供；實際來源以本機安裝紀錄與來源設定為準。兩個工具接續同一案件，不需要重新建立設計或重做網站。

完整流程：**安裝 → 確認案件匯入方式與套件 → Lin-EVO 切版並完成編輯標記 → 工具檢查、預覽與修正 → 客戶確認 → Miffy-EVO 最終檢查與打包 → 授權匯入與後台／前台驗證。**

只有修改需求時，直接從對應步驟開始。

## 1. 第一次使用：安裝並確認

### 在本機用 Codex 或 Claude Code

請 Lin-EVO／維護者協助安裝套件，告知你用的是 Codex 還是 Claude Code。維護者會依本機來源設定安裝兩個 Skill，你不用自行判斷 repo 位置。

重新開啟 AI 工具，貼上：

```text
請確認本機已安裝 Lin-EVO 與 Miffy-EVO。
請讀取各自的規範，告訴我是否可以使用。
如果缺檔或版本無法確認，請直接說明，不要重新安裝或覆蓋我的檔案。
```

AI 若回報找不到，將回覆交給維護者處理。不要只憑「已收到指令」判定安裝成功。

### 在 Claude 的 Skills 功能上傳

上傳維護者提供的 Lin-EVO＋Miffy-EVO ZIP 並啟用，使用包內的安裝說明。這是整合入口，同樣可以用「使用 Lin-EVO」或「使用 Miffy-EVO」指定工作。

Claude Skills 上傳環境與本機 Claude Code 不同：上傳 ZIP 不會讓它自動取得你電腦上的案件檔案，也不保證能連公司內網。若主要工作是直接修改本機網站與使用內網轉檔工具，優先使用 Codex 或 Claude Code。

### 規範會更新，怎麼辦？

本機 Git 來源以連結模式安裝的 Lin-EVO，直接讀同一份來源，修改後不必另行同步；每輪工作前偵測到 Git 就先安全更新來源，再核對連結並重讀規範；不需要另外複製。舊複製模式仍依規範更新副本。工程師的整站 HTML 套件 `evomni-html` **只能人工更新**：收到新版 ZIP 後，提供檔案位置並說「幫我更新工程師套件」，AI 會核對版本、替換來源、同步目前工具的安裝副本。每次切版與打包都重讀目前版本，不會自動找到工程師最新版。既有 JSON 案件才會依原流程檢查工程工具庫更新。

ZIP 是打包當下的版本。只上傳 ZIP 或從解壓縮快照安裝，不能當作 Lin-EVO 套件已有 Git 自動更新能力；需要更新套件時請維護者提供新包或設定 Git 來源安裝。Lin／Miffy 規則的 Git 更新、工程師 HTML 套件的人工更新、舊 JSON 工具庫的 Git 更新是不同來源；不能以其中一項更新成功推定其他項也最新。人工替換造成來源有未提交修改時，保留修改並做本機安裝同步，不強制拉取或自行提交。

AI 若說「尚未確認最新版」，先看原因是網路、認證或本機修改；請它整理處理方式，不要求強制覆蓋。

## 2. 開啟案件、準備資料

在本機工具開啟本案資料夾。先準備：

- **設計稿**：Figma 連結、截圖或檔案，包含要製作的頁面與狀態。
- **素材與文案**：Logo、圖片、字型與文字的位置，哪些是正式、哪些待補。
- **製作範圍**：本次頁面、設計稿尺寸，是否包含平板與手機。
- **既有網站**：已切好的檔案與進度，哪些畫面或動態已確認。
- **EVO 需求**：是否要匯入後台，哪些文字、圖片或清單要讓客戶自行修改。

EVO 工程工具來源已記在 Miffy-EVO，不需要你每案重新研究規格。案件若有指定工具位置、版本或站台，直接提供給 AI；尚未取得的就說尚未取得。

## 3. 使用 Lin-EVO 開始切版

複製下段，替換括號內的內容：

```text
使用 Lin-EVO（Lin-EVO），依本案設計稿製作網站。
案件位置：（完整路徑）
設計稿：（連結或檔案位置）
素材與文案：（位置；正式素材與待補項目）
本次頁面：（頁面名稱）
製作尺寸：（設計稿尺寸；是否包含平板與手機）
本案會使用 EVO 後台：（是／否）
客戶要自行修改的內容：（已知需求；不確定的請先幫我判斷）
請先讀目前工程與進度，沿用已完成的部分。
依設計稿切版，同步準備已確認支援的 EVO 可編輯結構，並保留完整可操作的靜態預覽。
程式規範、檔案分工與檢查請自行處理，缺少必要資料時用白話一題一題問我。
第一次製作網站時，一起完成 Cookie 提示及有內容的隱私權政策頁；政策未確認時標示草稿。
```

AI 應先確認範圍、既有成果與缺少資料。設計稿是視覺基準；尺寸按案件設定，不固定某個桌機寬度。

你不必提供「每個區塊要掛什麼標記」。AI 會先判斷消息、產品、FAQ、輪播等編輯需求；只有用途不明或增刪會影響已確認構圖時，才向你確認。

## 4. 開啟預覽、看畫面與試操作

```text
請先自行檢查完成的頁面，再幫我開啟預覽。
用白話告訴我要看哪些頁面、試哪些操作，以及還有哪些缺圖、暫代內容或未完成項目。
請按本案約定的尺寸檢查，並說明實際測過的範圍。
```

看結果時，分成兩件事：

| 檢查 | 你要看什麼 |
|---|---|
| 畫面 | 字體、圖片裁切、文字換行、圖文比例、排列與留白，是否符合設計稿 |
| 操作 | 選單、連結、按鈕、輪播、FAQ、回頂部與動畫是否正常；有手機版就用手機尺寸操作 |

AI 自查後，你仍要看實際畫面。客戶尚未提供的素材與政策文字，先列待確認，不把暫代內容當成定稿。

## 5. 提出修正、給客戶校稿

描述頁面、區塊、問題及希望的結果，附上設計稿或截圖即可，不需要猜 CSS 原因。

```text
關於我們第二區的標題太靠近圖片，請依這張設計稿調整。
只改這個範圍，保留其他已確認的畫面、動畫與 RWD。
請找出原因再修正，檢查是否影響共用樣式或其他頁面。
改好後開啟預覽，簡短告訴我改了什麼及需要檢查哪裡。
```

交給客戶前，請 AI 整理可看的頁面、查看方式與待補內容。若要上傳，提供目標位置與授權；沒有要求上傳時，先準備好版本與說明。

收到回饋後集中提供給 AI。客戶確認時，明確說是哪個版本：

```text
客戶已確認這一版：（版本或確認日期）。
確認範圍：（頁面與內容）。
仍待確認：（沒有就填無）。
請記錄在本案既有進度文件，後續保留這一版的設計與互動。
```

AI 已檢查、你已看過、客戶已確認，是三個不同狀態。

## 6. 使用 Miffy-EVO 轉成 EVO 匯入包

已完成靜態頁面後，貼上：

```text
使用 Miffy-EVO，將本案已完成的靜態頁面轉成 EVO 匯入成果。
案件位置：（完整路徑）
本次頁面：（頁面名稱）
客戶確認狀態：（已確認版本；或目前只是測試轉換）
目標站台：（已知網址或站台名稱；尚未取得就說明）
工程套件位置：（本案已有位置；沒有就請 AI 核對已安裝的套件）
請沿用 Lin 交接記錄的匯入方式與套件版本；整站 HTML 讀目前人工更新的工程師套件，舊 JSON 流程才檢查工程庫更新。
請辨明是首次匯入、既有後台資料換版，還是已匯入網站續改，說明本次哪些資料會更新。
保留原有設計、動畫與 RWD，完成本機轉換、驗證及匯入包。
整理正確的後台入口、樣式與互動接入步驟、素材及待驗證項目。
這次先準備交付成果，不操作後台匯入、上傳或發布。
```

測試轉換可以在客戶確認前做，但交付需如實標記。Miffy-EVO 應告訴你轉了哪些頁面、包在哪裡、有哪些差異及剩餘接入工作。

### 先分清楚匯入入口

- **整站 HTML**：依目前工程師套件，交付網頁與資源包給後台的整站匯入入口。Miffy 保留 Lin 已完成的結構，最後修改後重跑檢查再打包。
- **既有 JSON**：沿用以下頁面角色及本案原本入口，不把整站 HTML ZIP 放到單頁 JSON 匯入入口。

### 舊 JSON 流程：不同內容的匯入位置

| 要放進 EVO 的內容 | 作用 |
|---|---|
| 首頁 | 首頁內容及平台頁首／頁尾的對應，依工程規格處理 |
| 列表頁框架 | 一整組分類共用的側欄、列表與分頁 |
| 分類介紹 | 某個分類自己的介紹圖文，不重複整份列表框架 |
| 產品／文章內容頁版型 | 點進單筆內容後使用的版面 |

AI 應按案件已確認流程判斷並說明入口。只要某個分類的介紹，就說「只做這個分類的介紹」；不要將完整列表頁誤匯到介紹位置。

### 既有網站換版與續改

先提供本案原始資料夾與交接紀錄；舊站重畫另依工程師套件提供站台附件與來源畫面。已匯入的檔名及資料識別不要任意更換。換版模式若保留後台文章、產品、選單、表單與 SEO，這些內容修改需在後台另行處理，不能以修改包內文字當成已同步。

### 客戶可編輯，不只代表畫布看得到

Miffy-EVO 會處理可支援的逐筆編輯結構與資料對應，但仍須到後台實測。輪播在畫布會動，也不代表發布後一定有初始化；圖片在匯入包內，也不代表已上傳媒體庫。

## 7. 交工程師匯入，或授權 AI 操作

### 交給工程師

```text
請整理給工程師的 EVO 交付資料。
列出每頁的匯入包、正確後台入口、樣式與互動接入方式、客戶可編輯內容及待確認項目。
說明本機轉換與驗證結果、客戶確認版本，以及後台和發布後前台還要測什麼。
先不要自行匯入、上傳或發布。
```

你不用自己填工程對照表。工程師先核對本案匯入入口、預檢的頁面／資料對應及變更，再處理必要接入及串接。圖片處理依該入口；只有舊 JSON 契約要求時才使用「上傳到媒體庫」及占位圖片網址，不套用到新版 HTML 流程。

### 需要 AI 協助實際操作時

提供目標站台、頁面與操作範圍，例如：

```text
使用 Miffy-EVO，把已驗證的匯入包匯入指定 EVO 測試環境。
目標站台：（網址）
目標頁面與後台入口：（位置）
匯入包：（檔案位置）
本次授權：匯入及圖片上傳，不發布。
若目標已有內容，先依匯入範圍準備可還原的測試環境：整站匯入使用測試站或完整備份，單頁流程才用測試頁／副本。
先核對後台預檢的變更範圍，若超出本次授權先停止該部分。
完成後告訴我預覽位置與待驗證項目。
```

登入使用你已設定的登入環境，不把帳號密碼或存取憑證貼進公開文件。AI 必須有可用的後台操作工具及權限才能執行；沒有時仍可交付包與操作步驟。

## 8. 後台與前台驗收

| 階段 | 要確認的結果 |
|---|---|
| 匯入畫布 | 圖片、文字、排列與樣式正確，沒有漏區塊 |
| 內容編輯 | 能修改文字、換圖；允許增刪的清單測新增、刪除與排序，固定筆數只測允許的編輯；隱藏功能依實際契約 |
| 儲存重開 | 修改有保留，沒有被樣板或動畫舊值蓋回 |
| 發布後前台 | 內容最新、圖片正常、連結與互動可用，原有動畫及本案 RWD 正確 |

請測一筆長文字、不同圖片，以及清單新增或刪除後的畫面。FAQ、輪播等測實際存在的功能，沒有的功能不新增。

如果匯入後與靜態版不同，可貼：

```text
使用 Miffy-EVO，檢查 EVO 匯入後與靜態版的差異。
靜態來源：（位置）
EVO 頁面：（網址；問題發生在畫布或前台）
問題：（描述並附截圖）
請先找出是結構、樣式、套件載入、初始化或內容資料的原因。
以已確認的靜態版為基準修正，不重做設計，並說明修改位置與實測結果。
```

**匯入包驗證通過、客戶校稿確認、後台編輯通過、發布後前台通過，分開記錄。** 缺後台存取時，應寫「待驗證」，不能把靜態模擬當成已完成。

## 9. 下次繼續，不用從頭來

回到同一案件資料夾，依工作選 Lin-EVO 或 Miffy-EVO：

```text
使用 Lin-EVO／Miffy-EVO（保留本次需要的名稱）。
先讀本案進度與已確認版本，不要重新開始。
這次要做：（工作內容）。
請保留已確認的設計、內容、動畫與 RWD。
```

## 遇到問題時

| 狀況 | 可直接貼給 AI |
|---|---|
| 找不到 Skill | 「請確認安裝位置與檔案是否完整，整理結果給維護者，不要覆蓋現有檔案。」 |
| 無法開預覽 | 「請檢查本案的預覽方式並開啟，缺少工具時寫清楚處理步驟。」 |
| 工程師提供新版 HTML 套件 | 「這是新版 ZIP 的位置，請核對並更新 Miffy 的工程師套件，同步安裝副本，再重讀版本與規範。」 |
| 舊工程庫更新失敗 | 「請保留本機修改，說明原因與處理方式，列出哪些工作仍能繼續。」 |
| 缺素材 | 「請列出缺少的檔案與使用區塊，保留正式素材，不自行換成其他圖片。」 |
| 後台找不到逐筆編輯 | 「使用 Miffy-EVO，核對本案編輯標記、目標平台版本及實際匯入結果。」 |
| 畫布正常、前台不正常 | 「使用 Miffy-EVO，檢查發布資料、正式素材路徑、樣式與初始化，不只看畫布。」 |

以下只給維護人員，設計師不用閱讀：

- 工作規範：[Lin-EVO/SKILL.md](Lin-EVO/SKILL.md)。
- Miffy-EVO 規範以其獨立來源為準；本 repo 內若仍有舊目錄，只供舊安裝遷移，不作為新版工程師套件來源。單獨安裝：`python3 install.py --tool codex --skill Miffy-EVO`，Claude 改 `--tool claude`。每個 Skill 有獨立安裝紀錄，紀錄會保存實際 `skill_path`。
- 安裝程式：[install.py](install.py)。需要 Python 3 與 Git；從本 repo clone 到固定本機位置。Lin／Miffy 分開維護時，先核對 repo 內的 `skill-sources.json` 是否指向兩個實際來源；相對路徑以本 repo 為基準。Codex 使用 `python3 install.py --tool codex`，Claude 使用 `--tool claude`；需要只裝一個時加 `--skill Lin-EVO` 或 `--skill Miffy-EVO`。新安裝預設連結到各自來源；既有安裝未指定模式時沿用原模式。已管理副本改成連結時只會轉換未被自行修改的內容；需要獨立副本時加 `--copy`。先加 `--dry-run` 核對。
- 更新：Lin-EVO 可依其規範用 `--update --skill Lin-EVO` 安全更新。Miffy-EVO 的工程師套件採人工替換；人工更新後用不帶 `--update` 的安裝指令同步。只有在 Miffy 獨立 Git 乾淨、遠端已確認且確實要拉取其規範更新時，才對 Miffy 使用 `--update --skill Miffy-EVO`。斷網、來源或副本有修改、分歧時保留現況並明確回報。
- `--status` 只核對連結目標或來源與安裝副本，不連網；`--dry-run` 不寫檔也不更新遠端。安裝不保留舊副本備份，不影響其他 Skill。複製安裝以雜湊核對，已修改副本會保留並停止。
- 此 repo 是 Lin-EVO 共用規範與安裝管理來源。整體視覺與高效只保存方案差異；整站 HTML 契約由 Miffy-EVO 獨立來源內人工更新的 `evomni-html/` 提供；既有 JSON 使用的 evomni-page-composer 資料另行取得。
- 交付／安裝前確認實際 Miffy 來源含完整 `evomni-html/` 規範、範例與檢查器；不能以 lin-skill 內的歷史副本或已產生的舊 ZIP 宣稱同事已取得新版。本包不含客戶素材，也不含整體視覺提案流程。平台接入仍依工程師規格，未經實際轉檔不可宣稱已驗證。

## Skill 改名

正式名稱及資料夾為 `Lin-EVO`、`Miffy-EVO`，大小寫依此使用。受管理的舊安裝由 `install.py` 遷移名稱與安裝紀錄，再同步內容；會保留原有連結／副本模式。來源不同、副本有修改或新舊名稱同時存在時停止，不覆蓋。`--dry-run` 只列遷移計畫；舊名稱僅作安裝遷移相容，不再作為工作入口。
