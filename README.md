# Lin-EVO｜設計師切版與校稿操作手冊

更新：2026-11-10 · 適用 Codex、Claude Code 與 Claude 網頁版

本 repo 維護 **Lin-EVO**：依 Figma／設計稿製作網站、修改 HTML／SCSS／JavaScript、處理互動及校稿。你提供設計、素材、需求與確認畫面；LIN 負責讀取規範、實作、檢查及整理交接。

**Miffy-EVO 是另一個獨立 Skill 與 Git repo**，負責靜態網頁轉 EVO。兩者分別安裝、分別更新、分別打包；安裝 LIN 不代表已安裝 Miffy，更新 LIN 也不代表工程師套件已更新。

## 1. 第一次使用：安裝並確認

### 本機 Codex／Claude Code

請 AI 或維護者協助安裝 Lin-EVO，說明使用哪個工具。只需要切版與校稿時，指定只安裝 LIN，不連帶安裝其他 Skill。

```text
請安裝或核對本機 Lin-EVO。
我使用的是：（Codex／Claude Code）。
請讀取規範，確認安裝位置、來源版本與檔案是否完整。
保留我現有的修改，遇到來源不同或檔案衝突時說明原因，不強制覆蓋。
```

若工具尚未辨識到新安裝的 Skill，重新開啟工具或對話後再呼叫。安裝 Skill 不代表已安裝 Sass、Node 或預覽工具；案件缺少工具時由 AI 說明需要的設定。

### Claude 網頁版

上傳維護者提供的 **Lin-EVO 獨立 ZIP** 並啟用。需要 Miffy 時，另行上傳並啟用 **Miffy-EVO 獨立 ZIP**，不能合併成一個包。

ZIP 包含 LIN 規範與預設切版基底，是打包當下的快照，更新後須重新上傳。網頁版不能自動讀取你電腦上的案件、localhost 或公司內網；依工具實際可存取的方式提供檔案，不把本機路徑當成已上傳。

### 規範更新

- 本機採連結安裝時，直接使用同一份 Git 來源；來源更新後不需再複製，但要重讀規範。複製安裝則需同步副本。
- 工作前依 LIN 規範安全確認遠端版本；有本機修改、分歧或認證問題時保留現況，不強制覆蓋。
- EVO 整站 HTML 使用的工程師 `evomni-html` 套件由 Miffy 的獨立來源管理，依目前流程人工更新。LIN 切版需要該契約時會先核對實際版本，不以 LIN 已更新推定套件也最新。

## 2. 開啟案件、準備資料

在本機工具開啟本案資料夾。先準備：

- **設計稿**：Figma 連結、截圖或檔案，包含要製作的頁面與狀態。
- **素材與文案**：Logo、圖片、字型與文字的位置，哪些是正式、哪些待補。
- **製作範圍**：本次頁面、設計稿尺寸，是否包含平板與手機。
- **既有網站**：已切好的檔案與進度，哪些畫面或動態已確認。
- **EVO 需求**：是否要匯入後台，哪些文字、圖片或清單要讓客戶自行修改。

EVO 工程工具來源已記在 Miffy-EVO，不需要你每案重新研究規格。案件若有指定工具位置、版本或站台，直接提供給 AI；尚未取得的就說尚未取得。

## 3. 使用 Lin-EVO 開始切版

複製下段，替換括號內的內容：

```text
使用 Lin-EVO，依本案設計稿製作網站。
案件位置：（完整路徑）
設計稿：（連結或檔案位置）
素材與文案：（位置；正式素材與待補項目）
本次頁面：（頁面名稱）
製作尺寸：（設計稿尺寸；是否包含平板與手機）
本案會使用 EVO 後台：（是／否）
客戶要自行修改的內容：（已知需求；不確定的請先幫我判斷）
請先讀目前工程與進度，沿用已完成的部分。
依設計稿切版，同步準備已確認支援的 EVO 可編輯結構，並保留完整可操作的靜態預覽。
程式規範、檔案分工與檢查請自行處理，缺少必要資料時用白話一題一題問我。
第一次製作網站時，一起完成 Cookie 提示及隱私權政策頁；政策正文沿用 Lin-EVO 公版，只替換公司名稱，樣式接本案 root 變數。
頁面只要有電子表單，一律沿用 evo266125 contact-form 公版 HTML；只能改 CSS／SCSS 外觀，不另造表單結構或送出邏輯。
```

AI 應先確認範圍、既有成果與缺少資料。設計稿是視覺基準；尺寸按案件設定，不固定某個桌機寬度。

你不必提供「每個區塊要掛什麼標記」。AI 會先判斷消息、產品、FAQ、輪播等編輯需求；只有用途不明或增刪會影響已確認構圖時，才向你確認。

## 4. 開啟預覽、看畫面與試操作

```text
請先自行檢查完成的頁面，再幫我開啟預覽。
用白話告訴我要看哪些頁面、試哪些操作，以及還有哪些缺圖、暫代內容或未完成項目。
請按本案約定的尺寸檢查，並說明實際測過的範圍。
```

看結果時，分成兩件事：

| 檢查 | 你要看什麼 |
|---|---|
| 畫面 | 字體、圖片裁切、文字換行、圖文比例、排列與留白，是否符合設計稿 |
| 操作 | 選單、連結、按鈕、輪播、FAQ、回頂部與動畫是否正常；有手機版就用手機尺寸操作 |

AI 自查後，你仍要看實際畫面。客戶尚未提供的素材與政策文字，先列待確認，不把暫代內容當成定稿。

## 5. 提出修正、給客戶校稿

描述頁面、區塊、問題及希望的結果，附上設計稿或截圖即可，不需要猜 CSS 原因。

```text
關於我們第二區的標題太靠近圖片，請依這張設計稿調整。
只改這個範圍，保留其他已確認的畫面、動畫與 RWD。
請找出原因再修正，檢查是否影響共用樣式或其他頁面。
改好後開啟預覽，簡短告訴我改了什麼及需要檢查哪裡。
```

交給客戶前，請 AI 整理可看的頁面、查看方式與待補內容。若要上傳，提供目標位置與授權；沒有要求上傳時，先準備好版本與說明。

收到回饋後集中提供給 AI。客戶確認時，明確說是哪個版本：

```text
客戶已確認這一版：（版本或確認日期）。
確認範圍：（頁面與內容）。
仍待確認：（沒有就填無）。
請記錄在本案既有進度文件，後續保留這一版的設計與互動。
```

AI 已檢查、你已看過、客戶已確認，是三個不同狀態。

## 6. LIN 的預設基底與檢查範圍

切版及檢查都先讀 [內附基底規範](Lin-EVO/references/starter-baseline.md)。新案複製完整基底再製作；既有案比對必要差異，不整包覆蓋。

| 項目 | LIN 要遵守的規範 |
|---|---|
| Common／root | 沿用共用變數與元件，核對備用值、編譯與實際載入 |
| Header | 以 evo266200 結構與預設樣式為基底；1199px 以下漢堡、1200px 以上桌機選單 |
| 一般導頁按鈕 | `div.btn-group > a.btn-link`，依設計選主色、輔色或外框；Header 依其範本 |
| FAQ／分類側選單 | 優先沿用指定系統結構，再調整 CSS |
| 列表與內容頁 | 核對共用設計所屬上層分類與主列表替換範圍，依本案匯入契約處理 |
| 隱私權政策／電子表單 | 沿用指定公版，區分固定結構、可替換資料與可調整外觀 |
| 套件與動畫 | 依 EVO 載入契約；Lenis 1.3.26 已開放，需要時宣告並初始化，發布後驗證 |
| 完成檢查 | 視覺、互動、RWD、SEO、圖片容量與格式、工程師交接；未實測項目明列待驗 |

完整規則以 [Lin-EVO/SKILL.md](Lin-EVO/SKILL.md) 及其 references 為準，本表不取代詳細規範。AI 自查、設計師確認、客戶確認及後台驗收是不同狀態。

## 7. 完成切版，交接轉 EVO

LIN 完成靜態網站、校稿及本案唯一的 `工程師交接說明.md`。交接應包含已確認版本、實際檔案、匯入方式與工程師套件版本、可編輯需求、功能接入及待驗項目。

需要轉 EVO 時另行使用 **Miffy-EVO**；其操作以 [獨立 Skill 規範](../Miffy-EVO/SKILL.md) 為準。此相對連結適用維護者目前的相鄰資料夾配置；其他電腦依 Miffy 安裝紀錄定位，不假設它一定在本 repo 旁邊。本 README 不維護另一份 Miffy 操作規範。

切版完成或匯入包檢查通過，不等於後台已匯入、可編輯或已發布。實際上傳、匯入及發布另依授權處理。已成功轉 EVO 的案件依交接紀錄至後台續改，原靜態 Git 保留查閱，不繼續當成有效修改來源。

## 8. 下次繼續與問題回報

```text
使用 Lin-EVO，先讀本案進度與已確認版本，不要重新開始。
案件位置：（完整路徑）。
這次要做：（切版／修改／校稿內容）。
請保留已確認的設計、內容、動畫與 RWD，完成後記錄實測結果及待辦。
```

找不到 Skill 時，請 AI 核對安裝位置與來源；無法預覽時，請它檢查編譯、啟動方式及缺少的工具。缺素材就列出檔案與使用區塊，不自行替換正式素材。換電腦續作時先整理交接與版本，依授權 commit／push，另一台取得同一版本後再續作。

## 維護者：本機安裝與更新

從本 repo 根目錄執行，需要 Python 3；Git 更新另需 Git 及遠端存取權限。所有 LIN 指令明確指定 `--skill Lin-EVO`，避免安裝器預設同時處理其他 Skill。

```bash
# 安裝前先查看將進行的操作
python3 install.py --tool codex --skill Lin-EVO --dry-run

# 安裝或同步 LIN
python3 install.py --tool codex --skill Lin-EVO
python3 install.py --tool claude --skill Lin-EVO

# 核對本機安裝；不連網確認遠端版本
python3 install.py --tool codex --skill Lin-EVO --status
python3 install.py --tool claude --skill Lin-EVO --status

# 安全更新 LIN 來源並同步指定工具
python3 install.py --tool codex --skill Lin-EVO --update
python3 install.py --tool claude --skill Lin-EVO --update
```

新安裝預設連結到來源；既有安裝沿用原模式，需要獨立副本才指定 `--copy`。來源或副本有修改時保留現況，不能為通過更新而 reset、覆蓋或自行提交。`--dry-run` 不寫檔、不更新遠端；`--status` 只檢查安裝內容，不能據此宣稱遠端最新。

[skill-sources.json](skill-sources.json) 仍可供共用安裝器定位獨立的 LIN／Miffy 來源；這不代表兩個 Skill 合併。每個 Skill 有自己的安裝紀錄與 `skill_path`。舊名稱僅供安裝遷移相容，正式工作名稱為 `Lin-EVO`。

## 維護者：Claude 網頁版打包

使用固定程式，不用舊 ZIP 重包。檔名換成本次日期或版本，既有輸出不覆蓋：

```bash
python3 scripts/build_claude_upload.py --output dist/Lin-EVO-Claude-YYYYMMDD.zip
```

程式只打包 LIN，不包含 Miffy。上傳入口由 [Claude 包裝範本](scripts/templates/Lin-EVO-Claude.md) 維護；包內只有一個 SKILL.md，包含 LIN references、完整基底與必要空檔。程式檢查基底清單、雜湊、包內相對參考及 ZIP 完整性，來源版本與未提交狀態記在 SOURCE.json。

基底的 LIN 調整記在其 SOURCE.json，保留原始雜湊；修改後先核對並更新紀錄，不跳過驗證。打包不自動安裝、提交、推送或上傳 Claude；使用者上傳新版後停用重複的舊 LIN。Miffy 由其獨立來源另行打包。
